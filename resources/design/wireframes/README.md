# Wireframes Guide

## Overview

Wireframes are low-fidelity visual representations of a product's layout and user interface structure. They focus on functionality and user flow rather than visual design.

**Created by:** Ankit Saxena | **Purpose:** Educational Resource

## What are Wireframes?

- **Low-Fidelity**: Simple, sketch-like representations
- **User Flow**: Show how users navigate through the product
- **Information Architecture**: Display content hierarchy and structure
- **Interaction Points**: Identify clickable elements and interactions
- **Device Specific**: Design for desktop, tablet, or mobile
- **Stakeholder Communication**: Help teams align on product structure

## Types of Wireframes

### 1. **Paper Sketches**
- Quick, informal hand-drawn sketches
- Great for brainstorming and exploration
- Tools: Pen, paper, whiteboard

### 2. **Grayscale Wireframes**
- Digital, greyscale layouts
- Shows layout without design elements
- Tools: Figma, Sketch, Adobe XD

### 3. **Interactive Wireframes**
- Clickable prototypes with basic interactions
- Demonstrates user flows
- Tools: InVision, Figma, Axure

## Key Elements

- **Header**: Logo, navigation, search
- **Navigation**: Primary and secondary menus
- **Content Area**: Main product information
- **Sidebar**: Filters, additional options
- **Footer**: Copyright, links, contact info
- **Buttons & CTAs**: Call-to-action elements
- **Forms**: Input fields and validation
- **Modals**: Pop-ups and overlays

## Creating Effective Wireframes

1. **Define User Flows**: Map out key journeys
2. **Start with Paper**: Quick sketches first
3. **Document Interactions**: Note hover states, clicks
4. **Include Annotations**: Explain functionality
5. **Get Feedback Early**: Test with stakeholders
6. **Iterate**: Refine based on feedback

## Wireframing Best Practices

1. **Keep it Simple**: Focus on structure, not design
2. **Use Grids**: Maintain consistency and alignment
3. **Be Consistent**: Use same symbols and elements
4. **Label Everything**: Clear annotations
5. **Show Responsive Layouts**: Desktop and mobile versions
6. **Document Interactions**: Note dynamic behaviors
7. **Get Buy-in**: Review with stakeholders early
8. **Version Control**: Track changes and iterations

## From Wireframes to Design

- **Visual Design**: Add colors, typography, imagery
- **Prototyping**: Create interactive workflows
- **Handoff**: Pass to developers with specifications
- **Development**: Implement based on wireframes and design
- **QA & Testing**: Verify implementation matches wireframes
